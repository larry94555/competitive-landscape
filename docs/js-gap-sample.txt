# The sample for the JavaScript-rendering gap measurement.
#
#   cargo run -p landscape -- gap docs/js-gap-sample.txt
#
# ARCHITECTURE.md §5.5 asks two questions about *pricing pages*, so every URL here is a
# pricing page rather than a homepage. The decision it feeds — whether a headless browser
# is ever built — is worth more than the half hour it took to choose these.
#
# How they were chosen, so the number can be argued with:
#
#   * B2B SaaS with published prices, which is what this product mostly reads.
#   * A deliberate mix of stacks. Next.js, Nuxt and Rails-era server rendering fail
#     differently, and a sample of one framework measures that framework.
#   * A few known "contact sales" pages, because a page with no price is a finding rather
#     than a gap and the residual must not silently absorb them.
#   * Public pages only. Nothing behind a login, nothing a robots.txt asks us to leave.
#
# **This sample is small and it is not random.** Thirty pages chosen by one person is
# enough to tell 40% from 4%, which is the decision in front of us, and nowhere near enough
# to publish as a market statistic. BENCHMARKS.md says so where the number appears.
#
# A line starting with # is a comment. Blank lines are ignored.
